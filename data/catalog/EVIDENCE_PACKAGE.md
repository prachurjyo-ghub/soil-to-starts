## Rebuild and audit

The current shell has no `python`/`python3` on PATH, and the external Dataset virtual environment points to a missing interpreter. This session used the existing Codex runtime Python executable. No environment repair or package installation was performed.

```text
python -X utf8 scripts/build_crop_evidence.py
python -X utf8 scripts/build_crop_evidence.py --check
python -X utf8 -B -m unittest discover -s tests -p 'test_*.py' -v
python -X utf8 scripts/workflow.py check
```

The normalized builder uses only the standard library and makes no network calls. `--check` rebuilds into temporary storage and compares every generated byte. `receipt.json` pins inputs and generated outputs. Input text fingerprints normalize CRLF to LF and declare that method; compressed binary inputs and generated outputs use exact bytes. Source-PDF checksums remain exact byte hashes. Scoped Git attributes preserve generated/frozen evidence and upstream snapshot bytes on checkout. A content change invalidates the receipt, while ordinary input text newline conversion does not. This is reproducibility evidence, not scientific certification.

The formerly missing flat builder is now [scripts/build_planning_dataset.py](../../scripts/build_planning_dataset.py). It runs the preserved upstream builder in temporary storage, applies exact month aliases and compares **every resulting cell** with the repository CSV. It does not overwrite `assets/`. This path requires `openpyxl==3.1.5`:

```text
python -X utf8 scripts/build_planning_dataset.py --output cache/crop-flat-rebuild
```

The upstream builder and extraction/transcription/model-preparation/validation scripts are preserved unmodified under `scripts/vendor/bamis/`. Their original root-path assumptions remain. To re-extract PDFs, stage them in a **separate workspace** with `BAMIS_All_Crops/`, the vendored scripts under `scripts/`, and the preserved `scripts/transcriptions/`. Review upstream command help and OCR-model availability first; dependencies are pinned in `scripts/requirements-crop-evidence.txt`. Raw extraction was not rerun in this session. The included frozen extraction is sufficient for both builds above.

To intentionally refresh the snapshot from the existing external collection:

## Calendar identity and ordered entries

`calendar_id` identifies a **source document/table**, not a confirmed planting cycle. `source_entries.jsonl` gives every physical source calendar column its own identity and printed order, including rejected/ambiguous columns. `entries.jsonl` retains the 7,834 analytical rows and references those source entries.

Numeric matching alone initially left **221 analytical entries** compatible with multiple columns in the same source table. The next local preparation step replayed the original builder's stage-position extraction: every one of those rows has exactly one physical column matching its existing nonblank stage label. All 221 now have a physical `sequence_index`, leaving **zero unresolved analytical-to-column matches in this snapshot**. This establishes how the imported CSV was constructed; it does not validate printed stages, calendar cycles or scientific applicability.

[lineage_audit.json](normalized/lineage_audit.json) retains every original numeric candidate, its geometry-extracted stage, the selected source-entry ID and the prior ambiguous analytical entry ID. Consumers of the initial research snapshot must follow these ID mappings; the 221 provisional analytical IDs have been replaced with physical-column IDs. Other retained entry identities are unchanged. Blank, absent, fuzzy or tied stage matches never narrow candidates. Future unresolved matches still retain all alternatives with null analytical order.

There are **124 repeated crop/season/region/week groups**. All alternatives remain separate. Cross-year source order is restored from physical columns instead of sorting week 1 ahead of week 49. No ISO-week assumption, date conversion, year offset or cycle offset is invented. Missingness remains: 939 stage cells, two month cells, one humidity value and 25 wind values.

The unfiltered source-entry inventory contains **8,191 physical columns**, including columns in excluded source documents and compressed/nonstandard labels. It deliberately has a different denominator from the old builder's 7,927 examined columns, which were counted after document exclusions.
